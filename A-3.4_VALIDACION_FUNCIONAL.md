## 1. Cómo se probó, y por qué así

Tres decisiones de método, porque de ellas depende que el resultado signifique algo.

**1. No se le cree a la respuesta HTTP.** Cada POST se verifica con una **conexión
psycopg independiente del ORM de Django**. Si la vista mintiera, el ORM podría
repetir la mentira; una segunda conexión leyendo la tabla, no.

**2. Las guardas se prueban desarmándolas.** Las dos `CheckConstraint` no se dan
por vivas porque el serializador las repita: se hace un **INSERT directo contra la
base, saltándose el serializador**, y se comprueba que la base sola las rechaza.

**3. El contador de efectos externos se prueba antes de leer su cero.** Un
instrumento roto también marca 0. Se dispara una sonda deliberada y se confirma
que queda registrada (X0) **antes** de aceptar el 0 de X1.

### El entorno no podía tocar producción

El contenedor que ejecutó todo **no tiene una sola credencial de producción**
— medido, no supuesto:

```
$ docker exec a34-runner env | grep -E "DBHOST|DBUSER|DBPASS|WISPHUB|SMARTOLT|WHATSAPP"
ninguna credencial de produccion
```

Su única variable de base es `TEST_DATABASE_URL` → `pg-a34`. No es una promesa de
no tocar producción: es no tener con qué.

## 5. El Supervisor NOC IA: medido por efecto, no por lectura de código (§13)

*"El código no lo llama"* no es una prueba. Y **"0 escrituras" tampoco lo es si el
ciclo no tenía nada que hacer.**

Así que se le dio trabajo real: una orden programada, asignada, con técnico
principal declarado ausente ese día. Después se **instrumentó el cursor de
Django** para registrar cada statement que el ciclo ejecutó de verdad.

```
supervisor.correr_ciclo(org_a)
  → {'senales': 1, 'propuestas': 1, 'repetidas': 0, 'sin_analisis': 0, 'expiradas': 0}

statements ejecutados ............................. 20
escrituras a operaciones_disponibilidad ...........  0      ← lo que se quería probar
escrituras a operaciones_propuesta_supervisor .....  1      ← prueba que el ciclo SÍ corrió
operaciones_disponibilidad ........................  3 → 3
```

**El 1 de propuestas es la mitad importante de esa medición:** demuestra que el
ciclo estuvo vivo y produjo efectos, así que el 0 de disponibilidad significa
*"no escribe"*, no *"no había nada que hacer"*.

**Segunda vía, por si algún día llegara por HTTP:** un actor autenticado **sin
`Profile`** recibe 403 (E9b). No hay perfil para el Supervisor NOC IA, y
`EsJefeDeOperaciones` exige uno.

La medición, para que no quede como una afirmación:

se aplica porque `BYPASSRLS` la atraviesa, incluso con `FORCE`.

> **B-7 es lo que convierte la segunda capa en efectiva.** No se ejecutó: está

## 11. Observación encontrada durante la prueba — reportada, no corregida

**`manage.py` ignora `DJANGO_SETTINGS_MODULE` y fuerza `crm.settings`:**

```python
# django-crm/backend/manage.py
os.environ.setdefault("DJANGO_SETTINGS_MODULE", "crm.settings")
os.environ["DJANGO_SETTINGS_MODULE"] = "crm.settings"   # la segunda línea pisa la primera
```

Se encontró porque `manage.py migrate` con `crm.test_settings` en el entorno
**fue igualmente a las credenciales de `crm.settings`**. En este entorno no había
ninguna, así que falló contra `localhost` y no pasó nada.

> **Por qué importa:** cualquier comando `manage.py` ejecutado desde una máquina
> que sí tenga el `.env` de producción en el entorno apunta a **producción**,
> aunque quien lo lance haya pedido explícitamente otro settings. La segunda línea
> anula la primera.

**No se corrigió** (§31, §32). Se rodeó ejecutando las migraciones del entorno de
prueba por `call_command` bajo el settings correcto.
